## 一、这本书解决什么问题

## 四、核心概念速览（阶段 2 的知识浓缩，通用网络知识）

- **代理（proxy）**：客户端把请求交给中间人转发，服务端看到的是中间人 IP。正向代理服务"客户端"，反向代理服务"服务端"
- **隧道（tunnel）**：把一种协议封装进另一种协议里传输（如把流量套进 HTTPS），用于穿透只放行特定协议的网络
- **VPN**：在网络层（L3）建加密通道，通常整机流量都走隧道；与"应用层代理"的区别是接管范围与协议层级
- **DNS 污染（缓存投毒）**：域名解析被劫持返回假 IP——连接"成功"但去错了地方；README 给出的实测解法是换第三方 DNS（百度 180.76.76.76 / 阿里 223.5.5.5 / 腾讯 119.29.29.29）后 `ipconfig /flushdns`
- **TCP RST（连接重置）**：TCP 握手或传输中收到伪造的 RST 包强制断开——"为什么翻了墙也无法访问某网站"一书专章讨论
- **SSL/SNI 阻断**：TLS 握手明文暴露目标域名（SNI 字段）被识别后阻断连接；数字证书攻防围绕 CA 信任链展开
- **NAT 类型**：影响 P2P 直连成功率（游戏、通话），有提升方法
- **纯净 IP**：未被大规模滥用、风控评分高的出口 IP——决定了某些服务（AI/流媒体）是否可用

## 五、排障工具箱（学完原理后的动手抓手，评论区+README 汇总）

| 工具/命令 | 用途 |
|---|---|
| Wireshark | 抓包看真实网络流量（谁在发 RST、DNS 返回了什么） |
| `curl -v` | 看一次 HTTP 请求的完整握手细节 |
| traceroute | 看路由路径在哪一跳断掉 |
| `curl cip.cc` | 判断当前出口 IP/是否走了代理通道（README 原文推荐） |
| `ipconfig /flushdns` | 刷新本机 DNS 缓存（配合换 DNS） |
| DNSCrypt | 加密 DNS 查询，防污染（书中有专章） |

## 六、开发者通用代理配置（README 原样保留——这三段本身就是通用技能）

```sh
# git 客户端走 socks5 代理 / 取消
git config --global http.proxy 'socks5://127.0.0.1:1080'
git config --global https.proxy 'socks5://127.0.0.1:1080'
git config --global --unset https.proxy
git config --global --unset http.proxy

# 浅克隆：网速差时只取最新代码
git clone --depth=1 https://github.com/你的用户名/你的repo.git

# Mac 终端走代理（全局模式终端也不会自动走，必须另设）
export ALL_PROXY=socks5://127.0.0.1:1080
unset ALL_PROXY
```

```sh
# ssh 走代理（写入 ~/.ssh/config）
## HTTP 代理
ProxyCommand socat - PROXY:127.0.0.1:%h:%p,proxyport=8848
## socks5 代理
ProxyCommand nc -v -x 127.0.0.1:1080 %h %p
```
