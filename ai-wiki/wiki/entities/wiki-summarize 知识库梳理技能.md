# wiki-summarize 知识库梳理技能

> 对已有知识库做整体盘点与体检，自动生成结构化 SUMMARY.md 的 Claude Code Skill。

## 简介

wiki-summarize 是一个面向 llm-wiki 风格知识库的梳理技能。它不负责消化单篇素材，而是在知识库积累到一定规模后，做一次全局盘点：看清库里有什么、主题如何分布、哪些页面失联、哪些素材还没消化。

核心价值是把“知识库现在到底怎么样了”从主观感觉变成可核对的报告。报告同时给出问题清单和补全建议，便于后续 ingest 和维护。

## 解决什么问题

知识库长期运行后通常会出现四类问题：

- 页面之间链接失效，出现悬空链接
- 新页面没有任何入链，成为孤页
- raw 素材已入库但长期没有对应 wiki 页面
- 页面内容过短，或残留“待补充”等占位文本

人工逐页检查成本高且容易遗漏。wiki-summarize 用只读脚本先把客观问题扫出来，再让 agent 通读核心页面补充主观归纳，两者结合形成报告。

## 组成部分

- `SKILL.md`
  权威定义：适用范围、六步流程、报告模板、内容铁律、常见错误。
- `scripts/scan-wiki.sh`
  只读扫描器，输出六段体检结果，不修改任何文件。
- `README.md`
  面向调用方的配置与复用说明，是 SKILL.md 的配套手册。

## 适用范围

支持三种对象：

1. llm-wiki 风格知识库
   根目录有 `.wiki-schema.md`，包含 `raw/`、`wiki/`、`index.md`、`log.md`、`overview.md`。
2. 任意 Markdown 知识目录
   进入降级模式，仍可生成报告。
3. 多知识库目录
   一个目录下多个 `*/.wiki-schema.md` 时，每个库单独产出一份报告。

不适用：单篇文章总结、单页润色、单页 lint。

## 执行流程

1. 同步远端
   写库前先 fetch + `pull --rebase`，冲突则停下交用户。
2. 定位知识库根
   用户路径优先，其次当前目录，再次 `~/.llm-wiki-path`，都没有就问用户。
3. 结构扫描
   运行 `scan-wiki.sh`，得到全部客观事实。
4. 通读核心页面
   先读 schema / index / overview / log，再逐页读 topics 和 entities，sources 等浏览，raw 只看文件名。
5. 撰写报告
   写入库根的 `SUMMARY.md`；旧报告先改名备份。
6. 收尾
   报告绝对路径、主题数、页面数、问题数；默认不提交。

## 健康检查项

- 断链
  `[[链接]]` 与任何 Markdown 文件名不匹配。
- 孤页
  `wiki/` 下没有任何入链的页面。
- 过短页
  `wiki/entities/` 小于 1500 字节。
- 占位文本
  出现 TODO、待补充、占位、placeholder、lorem 等关键词。
- 未消化素材
  raw 文件名去掉日期前缀后，找不到同名 wiki 页面。

这些检查都是启发式：链接只按文件名匹配，未消化只看同名，过短按字节计算。报告需要说明其局限，不能把启发式结论当成绝对事实。

## 报告结构

固定六节：

1. 总览
   一句话定位 + 数字盘点。
2. 主题地图
   Mermaid 图，最多两层，节点不超过 20。
3. 分主题要点
   要点来自实体页实际内容，每条标注来源链接。
4. 素材覆盖
   raw 各分类的已消化与疑似未消化清单。
5. 健康检查
   逐条列出脚本发现的问题并说明影响。
6. 待补全建议
   最多 5 条，按优先级排列。

## 配置与安装

- 安装
  把 skill 目录链接到 `~/.claude/skills/wiki-summarize`，任何项目都能触发。
- 默认路径
  `~/.llm-wiki-path` 写单个路径或每行一个路径。
- 远端
  优先 `mywiki`，其次当前分支上游，最后 `origin`。
- 提交身份
  本仓库约定 `wanglei9927`，提交时用 `git -c` 指定。
- 平台
  Windows 必须用 Git Bash，不能用 cmd 或 PowerShell 直接跑脚本。

## 设计取舍

- 只读扫描
  扫描器不写文件，避免体检本身污染知识库。
- 不自动提交
  报告是否入库由用户决定，降低误提交风险。
- 禁止强推
  多 agent 协作下，`--force` 会覆盖他人提交，只能 rebase 后重推。
- 每库独立
  多库混写会让统计和结论互相污染。
- 客观与主观分层
  脚本给事实，agent 给归纳，两者不混在一起。

## 与 llm-wiki-skill 的关系

llm-wiki-skill 负责日常的素材采集、消化、查询和健康检查；wiki-summarize 负责阶段性全局梳理。两者都用 `.wiki-schema.md` 作为知识库契约，但输出不同：前者产出知识页面，后者产出总结报告。

扫描结果与 llm-wiki-skill 的 `lint-wiki.sh` 冲突时，以 `scan-wiki.sh` 为准，并在报告中注明差异。

## 不同素材中的观点

来自 [[2026-11-02-wiki-summarize-skill]]：

- 这是“体检 + 梳理”，目标是可阅读、可交付的报告，不是普通问答。
- 六步流程不可跳步，同步远端是写库前置条件。
- 报告的所有链接必须真实存在，缺失内容只能进入“待补全建议”。
- 默认不提交；推送被拒只能 rebase 后重推，禁止强推。
- 非 llm-wiki 目录走降级模式，报告结构基本不变。

## 适用场景

- 知识库积累到几十页后，需要一次全局盘点
- 多 agent 协作前，确认库的当前状态
- 定期健康检查，发现断链、孤页和未消化素材
- 交接知识库时，快速让新 agent 了解结构与缺口
