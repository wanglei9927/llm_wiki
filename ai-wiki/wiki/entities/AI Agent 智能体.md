# AI Agent 智能体

> 能够感知环境、推理、制定计划、决策并自主行动的 AI 系统

## 简介

AI Agent（智能体）是 AI 技术的高级形态。与传统的大模型对话不同，智能体具备自主感知、推理规划、工具调用和决策执行的能力，能够完成复杂的多步骤任务。

## 核心能力

### 1. 环境感知
- 理解用户输入
- 观察执行结果
- 感知外部信息
- 状态跟踪

### 2. 推理规划
- 任务分解
- 步骤规划
- 逻辑推理
- 问题诊断

### 3. 决策执行
- 选择工具
- 调用工具
- 评估结果
- 迭代优化

### 4. 自主行动
- 无需人工干预
- 自动重试
- 错误恢复
- 目标导向

## 关键技术范式

### ReAct 模式
**Reason + Act，推理 + 行动循环范式**

```
思考 → 行动 → 观察结果 → 重新思考 → 调整行动
```

先思考下一步做什么，然后采取行动，基于行动结果再进行推理，形成闭环。

### 工具调用方式
1. **Function Call**：大模型原生的函数调用能力
2. **MCP**：Model Context Protocol，标准化工具调用协议

来自 [[AI 核心概念 16 讲]]：
- 能感知环境、推理、制定计划、决策、自主行动的 AI 系统
- 完成复杂任务，可调用工具

来自 [[鱼皮 AI 编程技术]]：
- 是 AI 编程开发的四大核心业务领域之一
- 构建智能体的开发范式
- 打造能够依据推理自主采取行动的 AI 系统
- 开发涉及知识：任务规划、工具调用、交互 I/O、异常处理

来自 [[DeepSeek Harness 发布推文]]：
- 单会话 Agent 是"孤岛"：同时推进多任务需用户自己来回切换、自己记上下文
- DeepSeek Harness 提出 Super-agent 双层架构：Router 层负责对话、记全局、派活；Worker 层为每个任务开独立隔离会话并行执行，完成后向 Router 汇报
- 配套事件触发（群消息、邮件、代码评论、CI 结果自动投喂）与 Watchdog 看门狗（故障自恢复）
- 争议：有开发者（@r8tba）实现过类似"会议模式"后删除，认为方向错误；另有观点称 Claude Code 的 project 机制与之类似

来自 [[DeepSeek Harness README]]：
- 官方定义 agent harness 概念：把模型、工具、会话、权限、UI 组装成可运行智能体的运行时框架（dsh）
- Agent 能力边界：读写工作区文件、执行命令、委派工作（delegate）、维护计划（plan）
- 权限策略：敏感操作按当前权限策略在 Web UI 先征询用户批准，默认不静默越权
- 插件化扩展：能力以插件组合（Everything is a Plugin），支持其他模型与自定义 OpenAI 兼容端点

### 开发流程示例：视频网站开发
1. 深入理解任务内容
2. 推理梳理执行步骤
3. 明确需求、设计方案
4. 搭建框架、生成代码
5. 部署上线
6. 遇到问题 → 询问意见 → 重新推理 → 调整行动方案

## 能力范围

### 常见工具调用能力
- 天气查询
- 文件读写
- 网页运行
- 信息检索
- 终端命令执行
- 数据库操作
- API 调用

### 典型应用场景
- 自动代码生成
- 自动化测试
- 数据自动分析
- 多步骤任务自动化
- 智能客服系统

## 开发框架

### 企业级选择
- **LangChain4j**：完整的 Agent 工具链
- **LangGraph**：图结构工作流编排
- **Spring AI**：基础 Agent 支持

### 低代码平台
- **Dify**：拖拉拽方式构建 AI 智能体
- **Cursor**：内置 Agent 模式的 AI IDE

## 实用信息

### Agent vs 传统对话

| 维度 | 传统对话 | AI Agent |
|------|---------|---------|
| 自主性 | 完全依赖用户引导 | 自主规划行动 |
| 工具调用 | 需用户触发 | 自动选择调用 |
| 状态管理 | 简单上下文 | 完整状态跟踪 |
| 任务复杂度 | 单步简单任务 | 多步复杂任务 |
| 错误处理 | 用户纠正 | 自动重试恢复 |
