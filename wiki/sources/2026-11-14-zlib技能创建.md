## 核心观点

1. **skill 定位"找书/搜书/下书/推 Kindle/导微信读书"触发词全覆盖**：description 列出用户可能说的全部触发词（找书、搜书、下书、Z-Library、zlib、电子书下载等），命中即加载。
2. **四条核心铁律防越权**：①下载是写操作先征同意（报候选清单让用户挑）；②下书前必查配额（quota_remaining=0 不硬试）；③书 id 必须完整 `id:hash`（漏 hash 下载失败）；④密码不进对话（登录用户本人终端做）。
3. **六工作流结构对齐 aliyunpan-sync 先例**：status（状态检查）→ search（主用工作流，必加 --json）→ download → kindle → weread → browse，每个工作流给出命令模板与前置条件。
4. **搜索规范固化**：必须 `--json` 解析输出；支持 --ext/--year/--lang/--order 过滤排序；候选以"编号+书名+作者+格式/年份/大小"表格呈现供用户选择。
5. **故障排查表七项**：not logged in / 域名连不上 / 网络超时（代理 127.0.0.1:7897）/ 登录失败（cookies 导入）/ 配额耗尽 / 更新（zlib update）/ 未配置项引导。
6. **配套登记完成闭环**：跑 refresh-installed-skills.mjs 时发现脚本硬编码 Windows 路径 E:/llm_wiki（支持 SKILLS_DOC 环境变量覆盖），本机须 `SKILLS_DOC=~/文档/llm-wiki/ai-wiki/notes/本机技能与代理清单.md` 前缀执行——重要踩坑记录。

## 实操内容保留

### 搜索标准动作

```bash
zlib search "书名或作者" --json --count 10          # 基础
zlib search "linux kernel" --ext epub --json        # 格式过滤
zlib search "..." --year 2020-2025 --lang en --json # 年份/语言
```

候选展示格式：编号 + 书名 + 作者 + 格式/年份/大小 → 用户选 → 查配额 → 确认 → `zlib download "id:hash"`。
