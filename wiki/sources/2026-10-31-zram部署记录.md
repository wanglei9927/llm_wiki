# 2026-10-31-zram部署记录

> Surface Go 3 内核优化项目第一项：部署 zram 压缩内存交换（lz4，3.6G，优先级 100），与磁盘 /swap.img 分级共存，交换总量 4G → 7.6G。

## 基本信息

- **来源**：本机部署记录（原始副本：raw/notes/2026-10-31-zram部署记录.md）；工具 systemd-zram-generator 1.2.1（Ubuntu 源）
- **内核**：linux-surface 7.2.13-1-surface（zram 模块自带）
- **日期**：2026-10-31

## 核心观点

1. **zram 的价值**：把压缩内存当交换设备用（lz4 实测压缩比 2~3:1），换入换出速度比磁盘快几十倍，不磨损 SSD；对 8GB 内存的低功耗设备是最有效的"内存扩容"手段。
2. **算法选 lz4 而非 zstd**：内核支持 7 种算法（lzo-rle/lzo/lz4/lz4hc/zstd/deflate/842），lz4 压缩解压最快、CPU 开销最小，契合 Pentium 6500Y 的 2C2T 弱 CPU；zstd 压缩率更高但代价是 CPU 时间。
3. **与磁盘 swap 分级共存**：zram priority=100 优先承接换出，磁盘 /swap.img priority=-1 做兜底——内核优先用快的，慢的只收溢出；交换总量 4G → 7.6G。
4. **systemd-zram-generator 是标准工具**：Ubuntu 官方源自带（1.2.1），配置文件 /etc/systemd/zram-generator.conf 四行搞定，开机经 systemd generator 自动创建，无需 enable。
5. **四个踩坑点**（详见原文）：cat hot_add 会真的创建设备；hot_remove 参数是数字设备号；设备在用时 comp_algorithm 不可写；可靠重建顺序 = stop 服务 → 删设备 → 重载模块 → start 服务。

## 实操内容保留

### 配置文件（/etc/systemd/zram-generator.conf）

```ini
[zram0]
zram-size = min(ram / 2, 4096)
compression-algorithm = lz4
swap-priority = 100
fs-type = swap
```

### 可靠重建顺序（踩坑后总结）

```bash
sudo systemctl stop systemd-zram-setup@zram0.service
echo 0 | sudo tee /sys/class/zram-control/hot_remove   # 参数是数字设备号！
sudo modprobe -r zram && sudo modprobe zram            # 重载模块清状态
sudo systemctl start systemd-zram-setup@zram0.service  # 按配置重建
```

### 部署后状态

```
swapon --show:
  /swap.img   file      4G    1G   -1   （后备）
  /dev/zram0  partition 3.6G   0B  100   （优先，lz4）
交换总量：7.6Gi
```

## 原文精彩摘录

> zram-size = min(ram / 2, 4096)——虚拟交换设备大小取物理内存一半、上限 4G；zram 按需压缩存储，实际占用远小于此值（lz4 压缩比约 2~3:1）。

> swap-priority = 100——优先级高于磁盘 swap 的 -1：优先用内存压缩，磁盘只做后备。
