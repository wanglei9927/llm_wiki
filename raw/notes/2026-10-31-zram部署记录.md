# zram 部署记录（Surface Go 3 内核优化项目，2026-10-31）

> 用压缩内存替代部分磁盘交换，提升 Surface Go 3 的内存有效容量与响应速度。

## 背景

- 机器：Surface Go 3（Pentium Gold 6500Y，2C2T），8GB RAM（可用 7.2Gi）
- 部署前：磁盘 swap 文件 /swap.img 4G（priority -1），已用 1.5G；swappiness 60；内存 available 仅 1.4Gi
- 内核：linux-surface 7.2.13-1-surface（zram 模块自带）

## 方案评估

| 项 | 结论 |
|----|------|
| zram 模块 | linux-surface 内核自带（drivers/block/zram/zram.ko）✓ |
| 可用算法 | lzo-rle（默认）、lzo、**lz4**、lz4hc、zstd、deflate、842 ✓ |
| 算法选择 | **lz4**：压缩/解压最快，2C2T 低功耗 CPU 开销最小（zstd 压缩率高但 CPU 代价不适合 6500Y） |
| 官方工具 | systemd-zram-generator 1.2.1（apt：systemd-zram-generator）✓ |
| 尺寸 | min(ram/2, 4096) = 3.6G 虚拟设备（按需压缩存储，实际 RAM 占用远小） |
| 与磁盘 swap 关系 | 共存：zram priority 100 优先，/swap.img priority -1 后备（磁盘兜底） |

## 配置（/etc/systemd/zram-generator.conf）

```ini
[zram0]
zram-size = min(ram / 2, 4096)
compression-algorithm = lz4
swap-priority = 100
fs-type = swap
```

## 踩坑记录（重要）

1. **`cat /sys/class/zram-control/hot_add` 会真的创建设备**——评估阶段读了一次该接口，悄悄创建了一个默认算法（lzo-rle）的 zram0，导致后续 systemd-zram-setup@zram0 沿用既有设备、配置的 lz4 不生效。
2. **hot_remove 参数是设备号数字**：`echo 0 > /sys/class/zram-control/hot_remove` 删除 zram0；写 "zram0" 字符串报 Invalid argument。
3. **设备存在时 comp_algorithm 不可写**（Device or resource busy），需先删除设备。
4. **彻底重建的可靠顺序**：
   ```bash
   sudo systemctl stop systemd-zram-setup@zram0.service
   echo 0 | sudo tee /sys/class/zram-control/hot_remove   # 删除 zram0
   sudo modprobe -r zram && sudo modprobe zram            # 重载模块清状态
   sudo systemctl start systemd-zram-setup@zram0.service  # 按配置重建（lz4 生效）
   ```
5. **oneshot 服务"active (exited)"是正常状态**；`swapon --show` 可能延迟一两秒刷新。

## 最终状态（部署后实测）

```
swapon --show:
  /swap.img   file      4G    1G   -1   （后备）
  /dev/zram0  partition 3.6G   0B  100   （优先，lz4）
交换总量：7.6Gi（原 4Gi → 7.6Gi）
```

- 开机自启：zram-generator 是 systemd generator（/usr/lib/systemd/system-generators/zram-generator），启动时自动按配置创建，无需 enable
- 休眠注意：zram 不支持休眠写入；如需休眠需依赖磁盘 swap（当前 4G < 7.2G RAM，休眠本就需要更大的持久 swap）
- 回滚方法：删除 /etc/systemd/zram-generator.conf 后重启即可恢复原状
